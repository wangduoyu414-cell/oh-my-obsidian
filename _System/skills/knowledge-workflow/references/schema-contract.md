# Schema 契约

Schema 定义对象语义、身份、谓词、关系、来源权威性和合并规则。它不负责读取来源或生成产物。

## 最小内容

```yaml
schema_name:
schema_version:
object_type:
identity:
  primary: []
  secondary: []
  aliases: []
predicates: {}
relations: {}
source_authority: {}
merge_rules: {}
validation_rules: []
```

## 谓词定义

每个谓词按需要定义：

- 语义和允许值；
- 单值或多值；
- 单位、精度、时间和范围要求；
- 来源别名；
- 可接受信息性质；
- 来源权威性；
- 冲突处理；
- 是否允许自动应用。

同名字段若主体、单位、范围或含义不同，必须映射为不同谓词。不同名称若语义相同，可以在 Schema 中登记别名。

## 身份规则

- 优先使用稳定权威标识；
- 名称仅作为候选匹配条件；
- 组合匹配必须说明参与属性和阈值；
- 模糊匹配只产生候选，不自动合并；
- 无法确认时创建临时标识或待确认任务。

## 来源权威性

权威性按谓词定义，而不是按整个来源定义。Schema 应说明：

- 哪类来源可以提出更新；
- 哪类来源只可补充描述；
- 时间更晚是否足够；
- 范围不一致如何处理；
- 何时需要人工确认。

## 合并规则

- 事件追加；
- 多值属性去重；
- 单值当前状态按时间、范围和权威性更新；
- 关系维护方向和有效期；
- 冲突并存；
- 失效不删除历史；
- 推断不写入核验事实区。

## 新 Schema 的充分理由

只有当知识需要新的稳定身份、独立字段语义、关系或合并规则时才新增 Schema。仅新增一种展示、查询或来源结构不需要新 Schema。

Schema 变更必须说明兼容性、迁移范围、受影响对象、Validator 更新和回滚方式。
